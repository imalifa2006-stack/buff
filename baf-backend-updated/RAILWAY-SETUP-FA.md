# راه‌اندازی روی Railway و Neon

1. **قبل از انتشار**: از Neon بکاپ یا Branch بگیر. فایل `migration_railway_final.sql` را ابتدا روی Branch تست اجرا کن. در دیتابیس اصلی، طبق مراحل قبلی بیشتر ستون‌ها و جدول‌ها ایجاد شده‌اند؛ این فایل جدول `advisor_change_requests` را نیز اضافه می‌کند. اگر محدودیت وضعیت دیگری با نام متفاوت داری، اول آن را بررسی کن.
2. در Railway Variables مقادیر `DATABASE_URL`، `BOT_TOKEN`، `ADMIN_USERNAME=ali_fgi0011`، `ADMIN_PASSWORD` (رمز قوی محرمانه) و `DEV_MODE=false` تنظیم باشند. `DATABASE_URL` و `BOT_TOKEN` را تغییر نده.
3. حساب مدیر با نقش `admin` و یوزرنیم `ali_fgi0011` در Neon باید وجود داشته باشد. این نسخه برای ورود مدیر از رمز `ADMIN_PASSWORD` استفاده می‌کند؛ رمز را در GitHub نگذار.
4. در GitHub پوشه `baf-backend-updated` را با محتوای همین پوشه جایگزین کن و commit کن. Railway در Settings → Source باید ریشه سرویس را `baf-backend-updated` تنظیم کرده باشد. قبل از deploy از نسخه فعلی backup بگیر.
5. پس از deploy: `/api/health` را چک کن؛ سپس `/admin.html` را باز کن. اول مشاور را در فهرست مجاز اضافه کن. مشاور باید با همان یوزرنیم تلگرام ثبت‌نام کند؛ سپس درخواست دانش‌آموز را تأیید کند.
6. سه دانش‌آموز قدیمی که `advisor_id=NULL` دارند باید توسط مدیر به یک مشاور ثبت‌نام‌کرده و فعال وصل شوند؛ تا آن زمان از آنها گزارش قبلی حذف نمی‌شود. آنها را از پنل مدیر «تغییر مشاور» بده.

**محدودیت‌ها**: ورود مشاور از طریق Telegram Mini App است. افزودن مستقیم دانش‌آموز توسط مدیر حسابی با رمز ایجاد می‌کند، ولی رابط ورود عادی دانش‌آموز در این نسخه هنوز در صفحه اصلی فراهم نیست؛ برای استفاده باید ورود وب جداگانه اضافه شود. این نسخه روی Neon/Railway واقعی تست انتهابه‌انتها نشده است. قبل از انتشار عمومی، ورود و کنترل دسترسی را روی محیط آزمایشی تست کن.
